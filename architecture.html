Architecture Technique : Le "MadOS ISO Builder" V3

Bienvenue dans la documentation d'ingénierie avancée de la forge MadOS_ISO_Builder. Cet outil est conçu pour compiler un système d'exploitation bootable, hybride, contenant la totalité des optimisations matérielles exclusives pour ASUS ROG.

⚠️ Accès Restreint : Contrairement aux remasterisations Linux artisanales qui altèrent le noyau d'Ubuntu via des environnements chroot destructeurs, l'approche de MadOS V3 repose sur une architecture "Payload Carrier" moderne.

🏗️ 1. Philosophie du "Payload Carrier"

La méthode classique de remasterisation consistait à s'introduire dans l'image système, de modifier les registres apt, et de "forcer" des installations silencieuses. Cette méthode provoque très souvent des kernels panic au premier boot à cause des décalages avec AppArmor ou Systemd-resolvd.

La solution MadOS : Le script build_mados_iso.sh construit une image système (Ubuntu 24.10 standard), l'ouvre proprement via unsquashfs, et injecte silencieusement l'intégralité du script V2 intact directement dans la matrice des nouveaux utilisateurs /etc/skel/. Le système d'installation lit ce dossier et déploie le programme parfait sur le bureau du futur propriétaire.

⚙️ 2. Prérequis Systèmes de la Machine Hôte

  • Environnement : Distribution Linux native ou Machine Virtuelle fonctionnant sous Ubuntu/Debian.
  • Alerte : WSL (Windows) est fortement déconseillé en raison de l'absence des modules de partitionnement en boucle (loop).
  • Privilèges : L'accès root (sudo) est strict.
  • Dépendances automatiques : squashfs-tools, xorriso, mtools, fdisk.

🔬 3. Analyse du Pipeline Automatisé

L'orchestrateur exécute 5 phases séquentielles strictes pour générer l'OS :

Phase 1 : Acquisition de l'image de base (Oracular Oriole)

MadOS privilégie la branche 24.10 pour s'affranchir de la vieillissante version de KDE Plasma de la 24.04 LTS. Elle offre KDE Plasma 6 natif, la compatibilité Wayland absolue, et Mesa 24+ pour le gaming haute-fidélité.

Phase 2 : Démontage de la Matrice (Unsquashfs)

L'architecte démonte l'immense fichier filesystem.squashfs vers la RAM/SSD dans le dossier hôte. Le système de fichiers entier devient alors modifiable en tant que matrice root.

Phase 3 : Injection Silencieuse du Payload

Le script utilise rsync pour capturer la totalité de l'incroyable structure de MadOS V2 (Modules, format_scripts.py, Control Center, OpenClaw AI). Le vecteur d'injection cible : /etc/skel/Bureau/MadOS_Install/

Phase 4 : La Compression Multicœur (Repacking)

La partie la plus exigeante en charge CPU (jusqu'à 100% sur un multithread).

mksquashfs "$SQUASHFS_EXTRACT" "$ISO_EXTRACT/casper/filesystem.squashfs" -comp xz -b 1048576 -Xdict-size 100%
  • Algorithme LZMA/XZ pour réduire la taille ISO au maximum.
  • Recalcul automatique du Hash MD5 et de la taille de l'En-tête (indispensable pour l'installeur Subiquity de Linux).

Phase 5 : Ingénierie du Boot Sector (Forging par Xorriso)

Pour contourner les limites UEFI/SecureBoot des cartes mères ASUS ROG récentes, l'image est forgée au format hybride. L'extraction du Master Boot Record (MBR) original assure la compatibilité isohybrid-gpt-basdat. Le fichier final MadOS-ROG-V3-Plasma6-amd64.iso est prêt.

🛠️ 4. Guide de Dépannage

  • mount failed to setup loop device : Le nombre d'appareils "loop" générés par le Kernel hôte est épuisé (Fréquent sous Docker/WSL). Videz-les via losetup -D.
  • Crash de l'installeur Ubuntu sur le Live CD : Le MD5 Hash List est probablement brisé. Recompilez en vous assurant que md5sum.txt est généré correctement.
  • Gèle du PC durant Unsquashfs : La matrice écrase votre RAM. Prévoyez 20 Go d'espace NVMe libre pour compiler l'ISO V3.
