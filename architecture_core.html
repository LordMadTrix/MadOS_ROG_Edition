Architecture Core : Le Script d'Installation MadOS

Plongée au cœur de la conception logicielle de MadOS ROG Edition. Le déploiement du système repose sur une architecture modulaire et paramétrique en bash, conçue pour transformer un Ubuntu Server en machine de guerre Gaming, de manière 100% automatisée ou sélective (Menu interactif).

🚀 L'Orchestrateur Principal : Menu_Installation_ROG.sh n'installe quasiment rien de lui-même. C'est un chef d'orchestre ultra-rapide qui lit, appelle et coordonne les 26 sous-modules isolés selon les choix de l'utilisateur.

🏗️ 1. L'Interface TUI (Text User Interface)

Plutôt qu'un simple script défilant à l'aveugle, MadOS s'interface via whiptail. Ce module génère nativement des fenêtres de dialogue (menus, cases à cocher, barres de progression) directement dans le framebuffer du terminal de la machine, créant l'illusion d'une interface graphique avant même l'installation du Serveur X11 ou Wayland.

if ! command -v whiptail &> /dev/null; then apt-get install -y whiptail fi

⚙️ 2. L'Architecture "Sub-Modules" (Séparation des préoccupations)

Le code est strictement découpé en respectant le principe S.O.L.I.D. Chaque sous-script a une fonction et une seule. Si un module échoue, l'orchestrateur gère l'erreur (via set -e trappé), enregistre la trace dans /tmp/mados_install.log, et vous en informe.

01_systeme_base.sh

Noyau de l'OS. Installation de Xorg, sddm, et conversion de la timezone système (Asia/Seoul > Europe/Paris by default).

02_pilotes_gpu_auto.sh

Détection Hardware Intelligente via ubuntu-drivers autoinstall pour forger le driver NVIDIA/Radeon parfait pour votre puce.

05_bureau_kde_plasma.sh

La magie graphique. Installe kde-plasma-desktop et configure le Wayland display server.

22_cpu_undervolt.sh

Ingénierie matérielle bas-niveau pour les CPU Intel/AMD, manipulant les registres de tension pour réduire la température de 15%. (RyzenAdj).

🔬 3. Transmission d'États (Variables Multi-Modules)

Les variables globales (comme le nom de l'utilisateur $REAL_USER ou le chemin $USER_HOME) sont passées dynamiquement de l'orchestrateur vers les modules .sh en tant qu'arguments (via $1). Cela sécurise les droits d'écriture et empêche un module de polluer l'espace Root s'il n'en a pas besoin.

Exemple de mécanique de lancement isolé :

# Dans Menu_Installation_ROG.sh bash "$INSTALL_DIR/modules/04_arsenal_logiciel.sh" "$REAL_USER"

🔥 4. La Personnalisation "Zero-Touch" et le Python

Le module de sécurité et de nettoyage de syntaxe (format_scripts.py) est un utilitaire natif codé en Python. Son rôle est de parcourir l'ensemble du dépôt local avant chaque lancement pour effacer les dangereux retours chariots Windows (\r\n en \n). Cela garantit que le script MadOS ne plantera jamais, même si l'utilisateur l'a édité depuis un Bloc-Notes Microsoft.

L'optimisation des temps de réponse et du nettoyage de l'OS est quant à elle déléguée à 00_nettoyage_ubuntu.sh, qui désactive violemment les daemons de télémétrie Snap Canonical.

🛡️ 5. L'Intelligence "OpenClaw AI"

Le système n'est plus un simple script. Il englobe une instance locale d'intelligence artificielle légère, activable par 03_intelligence_openclaw.sh, agissant comme un co-pilote terminal surveillant la santé de vos paquets en temps réel.
